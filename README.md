# DSH Side Chat

作者：lalala.gpt

AI 协作：[OpenAI Codex](https://openai.com/codex/)（代码审阅、文档整理与开源发布）。

主聊留在左侧，临时追问放到右侧。为 DeepSeek Harness（DSH）提供贴近原生使用方式的侧边聊天。

## 核心体验

- 原生组件：复用 DSH 的消息、输入框、模型菜单、工具调用与审批界面，沿用熟悉的操作。
- 独立提问：创建独立侧聊，参考打开时的主聊文本快照，不复制主任务、待办或自动续跑队列。
- 多侧聊并排：通过 DSH 原生右侧栏标签和分栏组织多个侧聊，方便分别补问、解释和讨论备选方案。
- 有价值就保留：在标签菜单选择“转为主会话”，保留同一个 Session ID、Agent 和聊天记录，继续讨论。
- 打开不出请求：打开侧聊本身不提交模型轮次；发送消息后按所选模型与账号的实际规则使用额度。

适合一边推进主聊、一边澄清概念、追问细节或讨论其他方案的用户。侧聊有真实记录和原生工具权限；想保留讨论时请先转为主会话，关闭前请阅读下方的数据与清理说明。

> **0.3.0 · 实验性开源版本 · 非官方插件**
>
> 侧聊是真实、会落盘的 DSH 会话，不是临时隐身窗口或只读沙箱。关闭清理尚不保证彻底无残留，也未验证长期内存回收。需要保留记录时，请先使用“转为主会话”，不要用标签 × 做保留操作。

## 功能（0.3.0）

- 从主聊标题栏或右栏“开始”卡片打开侧聊；两处入口共用原生标签路径，“开始”页原位替换为侧聊。
- 创建独立根 Agent，不 fork 主聊，不复制主任务、目标、待办或执行队列；打开本身不提交模型轮次。
- 把打开时取得的用户/助手文本快照作为引用上下文，最多 48,000 字符、120 条消息（按转义前原文计）；后续主聊不自动同步。
- 通过原生动态上下文提供侧聊身份、本会话 ID 和创建时来源 ID；提示模型按需定向读取来源，而不是凭根会话拓扑猜测权限或全局搜索聊天。
- 使用 DSH 原生会话正文及输入交互，支持独立标签、折叠和切换；“开始”卡片使用内置双对话气泡图标。
- 通过标签菜单“转为主会话”，保留同一个 Session ID、Agent、消息与正在运行的任务，并按父会话当前归属继承工作区。

## 安装与使用

先从本仓库的 Code → Download ZIP 下载源码并解压，或执行：

```sh
git clone https://github.com/lalala-git/dsh-side-chat.git
```

源码仓库已包含客户端构建产物 lib/client.js，按下面的目录安装方式使用时不必先执行开发构建。在准备使用的目标 profile 中安装并启用插件，不要安装到另一份 DSH 配置中。

在 DSH 原生插件管理器导入源码目录，或导入维护者提供的版本安装包。源码仓库不提交安装压缩包；尚无正式发行资产时，可按下文自行构建。

按管理器提示正常重启。`link:` 安装更新源码后不必重复导入，但宿主代码变更仍需正常重载宿主；压缩包安装必须先导入更新后的包。**只刷新浏览器不能更新宿主接口**，也不要强制结束仍在运行的主任务。同版本包可能受安装缓存或去重影响，不保证重新导入即完成升级。

### 打开侧聊

在主聊标题栏或右栏“开始”页点击“侧边聊天”。新侧聊的初始消息区为空，引用上下文不作为主聊历史再显示一遍。侧聊沿用父会话的实际工作目录、可用 Agent 预设和模型选择；工具与权限仍由 DSH 原生配置决定。

### 侧聊身份与主聊来源

宿主在原生模型请求的动态上下文中注明插件名、本会话 ID、创建时来源 `sourceSessionId`、侧聊/已保留状态及快照条数；回答“你是否处于侧聊”不需要检查文件或搜索会话。来源 ID 不随主界面切换改变，不一定是此刻主窗显示的会话。

侧聊仍是独立根会话；`session_trace` 返回 root 或没有祖先，不代表创建来源不存在，也不能据此判断会话读取权限。来源 ID 只是定位信息，不是访问凭据。快照足够时优先使用快照；只有当前用户确实需要快照之外的来源记录时，才提示模型以该 ID 调用可用的原生授权只读会话工具。工具缺失或拒绝时应如实说明，不绕过、不自动全局搜索、不轮询同步。

这些是提示层约束，不保证模型每次遵守，也没有新增原生权限或跨会话读取接口。身份更新随宿主重载后**新建的侧聊**注入，不后台改写已经存在的 Agent。

### 转为主会话

**右键点击右侧栏顶部的侧聊标签标题**（不是正文或 ×），选择“转为主会话”。

1. 宿主先不可逆地撤销该侧聊的临时删除资格。
2. 根据原始父会话当前归属，调用官方工作区接口登记同一个侧聊。
3. 打开原生主聊天，再移除发起操作的那个侧栏视图；原主聊不会被清空或删除。

这不是复制、合并或重新创建会话。其他旧标签或客户端即使持有旧能力值，也不能再通过本插件删除已经转正的会话。

宿主撤销临时删除资格后，动态身份改为“已保留会话”，创建来源与冻结快照不变。该状态不代表工作区归类或主窗导航已经成功；界面可能仍保留侧聊视图，提示不会永久断言“当前仍是临时侧聊”，也不伪造浏览器位置。

归类或切换失败时保留原标签并提示错误，可按提示重试；撤销的删除资格不恢复。转正后应按 DSH 原生会话管理记录。运行句柄仍由插件持有，直至正常插件/宿主卸载；卸载可能停止该句柄，但不会通过本插件删除其历史，因此不能把转正理解为完整的运行时所有权移交。

### 工作区与目录

- “未分组”不代表目录在某个盘。分组依据工作区成员关系，不按盘符、同名标签或相同路径猜测。
- 转正时动态查找父会话所在工作区的稳定 ID，再调用 `workspace.attachSession`；不写死工作区名或安装路径，不移动文件，不改变侧聊的 `cwd`。
- 父会话未分组时继续未分组；目标已被用户手动归类时尊重现有归属。父归属不唯一、原生服务不可用或目录不相容时拒绝自动选择。
- 原生接口负责校验及持久化，客户端通过官方事件流更新。登记后会复核并发变化，但不存在跨会话全局事务，**不承诺回滚已经保存的归属**。
- 规则只作用于后续转正，不批量移动旧会话。重启前的旧视图仅允许记住首次明确提供的父来源，不因此恢复删除所有权。

## 数据、隐私与权限

### 引用上下文会去哪里

侧聊会写真实原生日志。打开期间不归档，也不能保证它不出现在最近会话列表；转正前不主动登记到某个工作区。

引用提取只选择用户/助手消息的 `text` 追加事件，不复制系统提示、工具结果、附件、推理、目标、队列、提醒或自动续跑状态。它不是浏览器当前可见 DOM 的快照；对消息替换、撤回后的最终可见状态，尚无完整事件重放验证。

父文本会进入新 Agent 的引用提示，**后续侧聊请求可能将它发送给所选模型提供商**。宿主还会提供本会话/来源 ID、保留状态和快照计数；按需读取的来源记录也可能进入后续模型上下文。没有自动脱敏：原消息里的个人信息、路径或密钥也可能被带入。打开不调用模型，不等于后续问答不会对外发送上下文或消耗账户额度。

引用中的角色、ID、权限声明及命令仍是历史数据，不能覆盖宿主身份或授权本轮操作。引用 JSON 的尖括号会转义，并关闭原生提示模板插值，使父文本中的闭合标签或 `{{...}}` 保持为字面数据；这只是提示结构加固，不是防注入保证或权限沙箱。

提示要求把父历史当引用，不继续主任务；但提示**不是硬性只读沙箱**。侧聊使用实际工作目录及原生权限预设，完全权限仍代表完全权限。请在 DSH 原生权限菜单选择合适模式。原生模型选择器还可能保存全局默认模型，这是 DSH 的行为；本插件创建侧聊时不主动保存默认模型，也不改图片通道配置。

### 信任边界

本插件面向受信任的本地 DSH 用户和客户端，访问控制依赖 DSH 宿主，没有另设账户、Origin 或多租户授权层。

删除能力值用于约束当前宿主持有的自建句柄、防止误删，不是隔离不可信 RPC 客户端的安全凭证：同一受信任宿主中的恢复接口可凭对应父/侧聊 ID 恢复能力值。不要据此宣称公网部署或多用户隔离安全；本项目未验证上层 DSH 的网络鉴权和 CORS。

能力值只保存在客户端内存中，不放进资源地址、DOM 或 localStorage。旧的任意会话登记/删除接口已停用，不按标题或 ID 前缀认领历史会话。

## 关闭、保留与已知限制

- 点击**尚未转正**的侧聊标签 ×，会请求校验自有句柄和随机能力值，预检存储路径与索引，然后请求归档停止、释放句柄、删除精确日志目录，并清理部分索引及工作区引用。主聊和其他未认领会话不属于这条删除路径。
- **不是安全擦除或完整回收事务。** 归档不等于所有后代 Agent/任务已停止；异步缓存、索引写回、共享附件与插件记录没有整体回收保证。本项目尚未证明长期使用不会增长内存。
- 失败可能发生在已经停止侧聊之后。预检或忙碌错误通常保留日志，按提示处理；若提示 `sidechat/partial-cleanup`，则可能是日志已删但索引未清完，**不要盲目重试，也不要假定历史仍完整**。
- 已打开侧聊的刷新、React 卸载、折叠或切换不是显式删除请求；创建尚未完成的临时页被取消时另有自建会话回收路径。刷新与创建取消的完整组合仍需 GUI 验证。
- 同一宿主仍持有记录时，刷新可恢复侧聊能力值；完整宿主重启后不自动认领旧会话，旧视图关闭仅释放视图。异常退出可能留下记录，请按原生会话管理处理，插件不批量扫描清除。
- 转正后的标签只释放视图，不走临时删除路径；但正常插件/宿主卸载仍会释放其持有的运行句柄。
- 创建入口有临时侧聊配额和最多 512 条幂等请求记录，旧视图的非删除性父来源记录最多 512 条。关闭/转正不会清除所有请求记录；这些计数限制不等于完整内存回收证明。达到宿主生命周期上限时，应正常重载，不要尝试按标题清理数据。

## 架构

```text
主聊按钮 / 开始卡片
  → 宿主 open（唯一请求标识，幂等）
  → 文本引用快照 + 实际 cwd / 模型 / 可用 Agent 预设
  → 独立根 Agent（不提交模型轮次）
  → dsh-resource://sidechat/session/<id>
  → 原生 SessionReference + SessionProvider
  → conversation.content({variant:'embedded'}, {slots:{views:FixedChatConversationView}})
  → 原生消息 / composer / 工具审批
```

源码结构：

```text
src/client/   原生 UI 接入、菜单、图标与限定样式
src/host/     RPC、自有会话服务、精确清理路径
lib/          随源码提交的客户端构建产物
scripts/      零依赖构建、打包、可信本地 ASAR 参考读取
test/        内存回归、磁盘夹具及本机官方契约测试
```

运行时安装包只有 8 个文件；白名单以 [package.json](<package.json>) 的 `files` 加包清单自身为准。开发源码、测试和脚本不放进运行时包，下面的开发命令应在**源码仓库根目录**执行，不适用于安装后的精简目录。

## 开发与测试

无需安装构建依赖。**构建会写入**已有的 [lib/client.js](<lib/client.js>)；缺少输出目录时会创建它：

```sh
node scripts/build.mjs
```

只校验已有构建是否对应当前源码，不写输出：

```sh
node scripts/build.mjs --check
```

只运行不调用磁盘夹具的安全回归：

```sh
node --test test/native.test.mjs test/bundle.test.mjs
```

受限 Windows 环境若禁止测试进程使用命名管道，可在支持该选项的 Node 版本中关闭测试进程隔离：

```powershell
node --test --experimental-test-isolation=none test/native.test.mjs test/bundle.test.mjs
```

完整测试通过 `npm test` 运行，**会在项目 `_scratch/tests/` 下创建并清理文件系统夹具**。如果环境要求新建文件前审批，请先获准，不要把完整测试称为“只读”。全部测试都不需要真实模型或真实会话删除；这也不等于已经完成真实 GUI/模型验收。

### 可选：可信本地 DSH 契约参考

PowerShell：

```powershell
$env:DSH_REFERENCE_ASAR = '<DSH 安装目录>\resources\app.asar'
node --test --experimental-test-isolation=none test/native.test.mjs test/bundle.test.mjs
```

未设置 `DSH_REFERENCE_ASAR` 时，本机官方实现检查会跳过；跳过不能算兼容性通过。只指向自己信任的安装包：读取助手不改写 ASAR，但契约测试**会执行从中提取的实现片段**。参考提取还依赖特定版本的文件路径、构建哈希和源码形态，参考变更时应先检查提取逻辑，不直接判定原生 API 已损坏。

### 打包与核验

先构建并运行完整回归，再显式生成新版本包：

```sh
npm run build
npm run check
npm run pack:local
node scripts/pack.mjs --check
```

[打包脚本](<scripts/pack.mjs>) 与 npm 使用同一份显式文件白名单，会拒绝未打包的入口和过期客户端。默认只创建新包；同名包存在时拒绝覆盖，须先确定版本和目标路径。`pack:local` 只负责打包，不执行会写夹具的完整测试；不要跳过前面的回归步骤。标准 `npm pack` 的 `prepack` 也只校验已有构建，不能替代完整发布验收。

仅更新**本地、尚未发布**的同版本候选包时，可使用：

```sh
node scripts/pack.mjs --replace-existing
node scripts/pack.mjs --check
```

原位覆盖模式只更新校验通过的已有同名普通文件，不新建临时产物，也不是可回滚的原子替换。正式发布后版本应保持不可变；代码修订应递增版本，不依赖同版本覆盖来升级用户安装。

打包固定文件顺序、tar 时间和权限，并打印 SHA256；客户端构建统一源码 CRLF 为 LF。**只承诺相同文件字节及相同工具链下的确定性设计**，未完成跨平台、跨 Node/zlib 的哈希一致性验证。
